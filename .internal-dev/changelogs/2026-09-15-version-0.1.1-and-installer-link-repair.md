## Change Summary

Advanced the complete Lyra repository from `0.1.0` to `0.1.1`, aligned Maven coordinates, runtime/compiler metadata, launchers, packaging, tests, fixtures, examples, and user documentation, and installed the new local CLI release. Repaired the installer’s atomic symlink replacement after GNU `mv` followed the existing directory-valued `current` symlink and left the stable launcher on the prior release.

## Behavioral Impact

Lyra artifacts and installed release paths now use product version `0.1.1`. The installer now replaces symlink destinations themselves using GNU no-target-directory or BSD no-dereference `mv` behavior, preventing upgrades from silently placing temporary links inside the previous release. The local stable launcher resolves to `versions/0.1.1`, reports `Lyra 0.1.1`, retains `0.1.0` for rollback, and uses a newly generated Java 25 AOT cache.

## Specification Impact

Updated `.internal-dev/specifications/decisions.md` to identify `0.1.1` as the current SemVer release. Language contract 2, runtime ABI 1.1, artifact schemas, and source-language behavior are unchanged.

## Risks

The installer requires an `mv` implementation supporting either GNU `-T` or BSD `-h` for atomic symlink replacement; it now fails explicitly rather than performing a non-atomic fallback when neither is available. The full Maven suite was not rerun to completion at the user’s direction; the version-sensitive metadata test passed and the complete reactor package build succeeded with tests skipped.
