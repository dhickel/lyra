## Key Takeaways

- Imported aggregate ownership is an explicit origin path with exact tuple-member/array-index selectors, not a declaration-wide taint bit or a nesting-depth count. Unknown selectors are wildcard routes and are conservative; exact selectors discard unrelated siblings.
- A whole-binding reassignment replaces the binding's current origin set. An array-element assignment replaces the selected route while preserving unrelated sibling routes and prefixes the assigned value's exact nested routes.
- Resolver-time type absence is expected for inferred branch and aggregate expressions. Array, tuple, member, and index selections must preserve and adjust origin depth even when the checker will establish the concrete type later.
- A statically known identity-preserving lambda call propagates only the origins of arguments that flow to its returned aggregate. Callable parameter bindings must carry both the argument provenance and its exact source expression/scope so higher-order calls can be evaluated positionally. A fresh aggregate-producing lambda does not inherit argument provenance.
- Resolver aggregate and callable state is flow-sensitive: conditional/coalesce branches join reachable states, whole-binding rebinding replaces the current state, selected aggregate assignments replace only their route, and lambda-body analysis restores enclosing state because lambda creation does not execute its body.
- Callable discovery must select through array literals/indexes and tuple/member projections before applying call parameter-to-return flow; a function-valued aggregate is not equivalent to an arbitrary aggregate-returning function.
- Eager analysis binds statically known call arguments to lambda parameters for direct, namespace, and callable calls, and known calls must execute with those positional bindings. Tuple-container member routes and a complete nested array selector queue must be retained when applying element replacements so an unrelated callable member is not tainted.
- Eager callable candidates are source-position-sensitive: a later whole/function or aggregate-element assignment cannot affect a call that occurs before it. Assignments in non-executed lambda bodies must not leak into an enclosing module flow; recursive call guards remain separate from value-cycle detection.
- Eager value traversal needs an active declaration set in addition to a completed-visit set: re-entering an active non-lambda initializer is a same-module or cross-module eager cycle, while creating a predeclared function slot remains legal until a call executes its body.
- Tuple fields remain non-assignable, but a legal array index below a tuple member derives its mutation root through `MEMBER_ACCESS`; the same root traversal is required by typed semantic provenance and closed-IR validation.
- Inferred nil context can occur inside a composite branch, such as `Array[#NIL]`. Derive a structural expected contract from the peer branch before retrying the nil-containing branch, and make provenance validation repeat that derivation without reading the published type as authority.
- A summary for three-or-more operand short-circuit forms needs separate continuing and joined-exit states. Feeding the joined may-state into the next operand invents paths where an earlier operand was both skipped and evaluated.
- Predicate bindings must be seeded from the evaluated predicate formula under the narrowed binding contract before the truthy branch is summarized. Direct-call targets must likewise consult the current lambda state before reconstructing a declaration target, including captured shared-cell rebinding.
- Direct-call syntax does not imply a statically fixed lambda identity. A direct target may be a parameter, capture, or prior call result; the solver must retain that symbolic target and let ordinary caller substitution recover its exact finite identity. An identityless or unknown alternative remains `MISSING_CALLABLE_FACT`, including when another target alternative is valid.
- A function-valued declaration initialized by a call, projection, block, or other computed expression is not a declaration-to-lambda alias. Callable-summary compilation retains a declaration formula for that exact binding, and the canonical typed flow evaluator substitutes its current source-ordered `ValueAlternatives` at invocation. Imported namespace values use the same path. Never recover these declarations by scanning same-signature lambdas.
- Solver-time materialization must also defer a known higher-order call when a parameter/capture containing callable structure occurs in its target, arguments, or nested closure environment. Caller-time application must classify that call as unmaterialized so transferred writes, ownership requirements, and effects are not discarded into temporary duplicate-suppression lists.
- Reading an imported computed function value is an eager value read even though reading a directly linked immutable lambda slot is not. Mutable direct function slots also require the canonical current declaration value after source-ordered rebinding. Keep their initializer lambda only as a bounded potential SCC edge; do not publish it as the current declaration-to-lambda identity. Retain the original call/access kind and producer-issued flow site while materializing the declaration through the canonical evaluator; the exact resulting lambda creation site and capture/shared-cell snapshots are the callable identity.
- A local mutable recursive lambda may escape after its lexical declaration state has left the module frame. When its summary references its own owner declaration and no current binding fact exists, resolve that declaration to the exact currently invoked `CallableFlow` before attempting eager declaration lookup. Treating the local owner as a module declaration fabricates declaration values/events and fails sealing provenance.
- Closure creation does not run the nested body, but capture reads are eager facts. Canonical capture events must retain the direct cross-module read and any effects needed to materialize the captured declaration.
- Intrinsic callable discovery is an explicit declaration-to-module index that includes selective/re-export aliases. Intrinsics participate in finite higher-order target unions as effect-free scalar transfers while their call witnesses retain the intrinsic module dependency; they are never recovered by scanning compatible signatures.
- Mutable-parameter writes into concrete scalar, declaration-backed, or fresh caller-local arguments are complete non-escaping transfers, not missing callable facts. Parameter and captured-cell arguments still rebase into caller-visible writes.
- A published ownership witness keeps the allocation origin span/site separate from the later use span. Aliasing, importing, capture, or call transfer may change the occurrence site but must never replace the canonical allocation origin with a later reference span.
- Allocation identities may remain compilation-local abstract tokens, but only the canonical producer allocates them. The sealer must not repeat the allocation ordering algorithm or accept a synthetic scope fallback; the producer-issued origin `FlowSiteId` and exact owner scope are authoritative.
- A producer certificate must be bound by Java object identity to the exact `TypedSemanticCore` instance analyzed and returned. Equal records and deterministic flow-site maps do not make a reconstructed core the certified instance; a borrowed certificate must fail even when every content field compares equal.
- Mutation provenance includes the exact root `ReferenceId` from the assignment target. Same-module references to the same mutable declaration are distinct source sites and cannot substitute for one another in resolved or typed mutation indexes.
- Reference binding is itself producer provenance. A matching name, module, lambda owner, and edited `SyntaxLink` cannot prove which source-ordered declaration or sibling scope a source identifier selected. The resolver freezes each exact reference decision, indexes it reciprocally by declaration and scope, and binds that authority to the one resolved graph accepted by type checking and sealing; structural validation separately rechecks innermost source scope and lexical ancestry/source order.
- Source import headers and the canonical logical-module map are the authority for import topology. A `ModuleGraph.Edge` uses the exact `ImportPath.span`, not the full import declaration or another known source span; header-edge comparison includes that span together with source/logical/target and multiplicity. Import declarations, module/global bindings, target exports, public/re-export declarations, and flattened ultimate origins must also be reciprocal and source-complete before flow facts can be sealed.
- Capture completeness cannot be inferred from the supplied `ResolvedReference.capture` and `ResolvedCapture.references` fields alone because both ends can be removed consistently. Derive the required capture chain from the reference's exact lexical scope, target declaration scope, and enclosing-lambda ancestry. One capture exists per `(lambda, declaration)` pair; direct references are source ordered, transitive intermediate captures may have no direct references, and the capture span is the first source reference whose ancestry requires that slot. Capture mode is exactly declaration mutability, with the captured declaration as the shared-cell identity for mutable captures.
- A pre-typing resolver must not replay callable bodies. Every callable, direct, and namespace-direct call invalidates its bounded ownership projection at call entry, before resolving the target or arguments and independently of whether resolver type/signature metadata exists; selected aggregate writes invalidate it as well. Only canonical typed flow has solved summaries and identity-wide alias propagation. The resolver may still reject direct, source-local imported routes before that boundary; after it, canonical analysis preserves the same `LYC-RESOLVE-022` diagnostic before publication.
- Namespace member access is a declaration-collection leaf because its path and member name contain no expressions; namespace direct call is not. Its path and target name remain leaves, but every `argumentExpressions()` entry must be recursively collected once in source order before resolution so nested lambdas, blocks, declarations, aggregate allocation sites, and mutations own canonical identities/scopes rather than reaching later phases uncollected.
- Static imported ownership cannot be reconstructed only from transferred writes. Every aggregate-mutation container and every `@mut` argument is a source-ordered `OwnershipRequirement` in the callable summary, even when a body is uninvoked or the callee performs no write. Requirements share formula/capture/higher-order/SCC substitution with ordinary summary transfer and retain exact `FlowSiteId` plus diagnostic span.
- Branch, coalesce, and short-circuit summary writes must encode may-state at the transferred caller boundary. A write reachable on only one path joins its replacement with the pre-branch value; writes on both full-conditional branches join the two replacements without retaining an unreachable old value.
- Diagnostic origin is occurrence-specific even when two local import aliases share one aggregate identity. Canonical call transfer keeps an ephemeral `(use module, identity origin, occurrence span)` mapping so an unrelated alias cannot add or replace the exact related import witness; a foreign hidden aggregate instead uses the exact callable boundary span.

## Project Relevance

These rules protect the module-owned mutation boundary while allowing binding-local `@mut` permission to mutate nested identity-bearing arrays. They also keep source spans for imported origins available for related diagnostics and prevent stale ownership from surviving flow-sensitive replacement.
