# JVM Emitter Validation Knowledge

## Phase 15 scalar emitter invariants

- `U8` and `U16` use JVM `byte`/`short` raw storage. JVM narrowing after a valid result can leave a negative signed local (for example U8 255 is `-1`). Every later arithmetic, equality, or comparison that interprets a narrow unsigned local must normalize it with the unsigned mask before use. Normalizing only initial operands is insufficient for variadic left folds and exponentiation.
- The semantic checker intentionally retains a signed minimum literal as its positive magnitude under a unary-minus operator (`2147483648I32`, `9223372036854775808I64`). The generic runtime minimum-overflow check cannot distinguish those magnitudes from wrapped runtime minima, so the emitter must materialize the negated constant directly before entering that path.
- Nullable state storage is represented as separate presence and payload members. Generated getter dispatch must identify the exact `$isPresent$` accessor rather than relying on a broad `$present` substring.
- Reference value equality is consistently emitted through `Objects.equals`; primitive identity/equality paths remain separate.

## Validation pattern

Use both Class-File API loading/invocation tests and an external `java -Xverify:all` process. The external check should include a nontrivial generated method, not only a constant getter, because invalid stack shapes can hide on unexecuted branches.

## Callable-call emission gotchas

- A broad `StackOverflowError` try region may begin before target/authentication/argument emission while the ordinary `LyraRuntimeException` region begins immediately around the invoke. An out-of-line inner exception handler executes outside an enclosing call's protected bytecode range, so the outer handler cannot append target/argument frames after the inner handler translates the overflow. Capture lexical call-boundary spans while emitting nested target/argument code and append them in the inner handler in callee-to-caller order. Assert one frame per boundary and an exact `StackOverflowError` catch; never catch `Error` or `VirtualMachineError`.
- A typed Java facade call into a user function is a host entry, not another nested source-level Lyra call. Its exception table must catch existing `LyraStackException` and exact `StackOverflowError` independently, appending the facade module frame only for `LYR-STACK`; a broad `LyraRuntimeException` catch that appends an ordinary module frame recreates the throwable, changes the pinned Java failure trace and added roughly 2,432 B/op in the Phase 23 generated-failure row.
- Shared nominal-member delegate classes are keyed as source-independent structural types across session generations. Embedding `memberSpan()` constants, line tables or source-frame handlers in those classes changes bytes under one stable binary name and produces `session structural type definition changed`. Keep source mapping in the generation-specific caller boundary.
- Per-instance expected-signature fields may be `final` only if lifecycle close does not zero them outside `<init>`. They are inert metadata rather than retained live authority; state close must clear value/dependency storage while leaving final signature metadata untouched. Planner/IR ABI parity must independently inventory these fields, including unproved direct-name calls that correctly fall back to dynamic authentication; collecting only dynamic `CallableCall` signatures leaves generated direct-call authentication without a field.
- Nilable function coalesce joins need both branches retagged to the preplanned generated function interface before the stack-map merge. Executing only one branch is not enough validation; compile, verify and invoke both nil and non-nil paths plus a coalesce used directly as a call target.
- Opcode-only comparison is not control-flow parity. Compare branch/switch destinations, local slots and exception-table ranges through instruction-index-normalized labels, and fail on an unbound label instead of assigning every missing label `-1`. Inspect the generated member getters/adapters too: equivalent caller `invoke` methods alone cannot prove the absence of getter-side `resolveSignature` calls.
- To test a callable write or dynamic invocation boundary, inject a foreign SAM into a live Java array during an I/O effect after entering the Lyra function. A value rejected earlier at entry does not prove write/call authentication. Assert the effect happened and the foreign SAM was never invoked.
- Do not blanket-authenticate callable-bearing aggregate storage to establish a named-call proof. `NominalSessionTest.delegatedAndRawCallablesCoexistInAggregatesWithoutCrossBlessing` deliberately stores routed and raw occurrences together; only the authorized selection may execute. Such an eager-check experiment failed that regression during the final issue-#6 escalation and was removed. Named scalar callable writes remain authenticated and aggregate/index targets remain dynamically authenticated.
- A nominal route's receiver site must match the receiver child of its authorized semantic source expression, not only the candidate IR receiver and candidate proof. Validate that correspondence independently; otherwise a same-type receiver substitution can change selection while retaining a plausible member/schema proof.
- A generated nominal constructor that initializes per-instance signature metadata by calling `resolveExpectedSignature` on `this` must push the receiver twice: `invokevirtual` consumes its receiver, and the single surviving stack value is the returned `LyraSignature`, so a following `putfield` underflows without the extra receiver load. The Class-File API stack-map generator reports this as an operand-stack underflow at the `putfield`, not at the call.
- Nominal class shape is admitted in four independent places: `NominalClassLayout.members()` (the only member source, enforced by `GeneratedClassPlan`'s exact-layout equality), `GeneratedClassPlan.validateInstanceSignatureFields`, `JvmAbiParity.compareInstanceSignatureInventory`, and the runtime `SessionTypeLoader` nominal field-inventory admission. Adding any new nominal field kind requires all four, and `SessionTypeLoader` must admit only the exact deterministic metadata shape (private, final, non-static, `LyraSignature` descriptor, `$lyra$signature$` plus 16 lowercase hex chars) rather than a broad extra-field allowance. Constructor-time metadata resolution runs under the producer's CREATING/INITIALIZING/OPEN lifecycles through `LyraOwnershipToken.resolveSignature`, so it is legal exactly after `LyraNominalConstruction.begin` has bound producer authority and the exact schema, and fails closed on FAILED/CLOSED producers.
