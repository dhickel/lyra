# Complete the trusted Lyra REPL: persistent modules and live application attachment

## Feature

Finish the existing direct-Java-25-bytecode REPL rather than rebuilding its delivered compiler, persistence, console, and transport foundations. Deliver local console and headless Java evaluation, files and persistent module imports, explicit REPL-owned module reload, and live attachment to an explicitly enabled application. Apply the user's approved simplifications: localhost attachment without authentication or credentials; trusted typed linking instead of REPL-specific anti-forgery/capability isolation; a clean replacement of the pre-release remote API/protocol; and no automatic local application-root initialization. Preserve language semantics, normal AOT behavior, the existing synchronous local Java session API, initialization/thread/lifetime correctness, and already working persistent values. The implementation domains below are dependency-ordered instructions with concrete contracts and acceptance gates for less experienced agents. This plan supersedes conflicting REPL requirements in the earlier job only where explicitly identified here. No implementation or build execution occurred during this planning job.

## Required Behavior

- R01 — Preserve the delivered baseline: persistent scalars, arrays, tuples, named functions, higher-order calls, returned closures, recursion, mutable captures, lexical replacement, bounded immutable result snapshots, non-executing type queries, source-origin mapping, and failure/cancellation effects. Extend these paths; do not replace them with an interpreter, copied values, fake initializers, serialized IR, or transcript replay.
- R02 — Deliver local plain/JLine consoles, the existing local Java evaluation API, and live application attachment. The user expressly retained application attachment and user-module imports. Neither may be reclassified as deferred merely to finish the audit.
- R03 — Local sessions start empty. Keep the implemented directory meaning of `lyra repl [SOURCE_DIR]`: it supplies a module search root, not an application root to initialize. Add repeated `--source-root DIR` using normal resolution rules. Use `:load FILE` or explicit imports to bring code into the session; neither automatically invokes main. Remove the previous automatic local-root initialization/root-retaining-reset requirement from current scope.
- R04 — Support ordinary leading import headers in any submission, including after earlier definitions. Persist namespace aliases and selected imports; reuse initialized module instances within a workspace epoch; support normal aliasing, selection, re-exports, visibility, function cycles, and eager-initialization diagnostics. Missing/ambiguous modules and conflicting names remain structured source errors.
- R05 — Complete `std->io` end to end through the real REPL. Its compiler-owned identity remains special: do not treat it as a user-pinned source file, allow resolver replacement, or implicitly import it. Its aliases and function values must remain usable in later submissions, including alongside retained aggregates and callables.
- R06 — Pin ordinary imported source revisions until explicit reload/reset. Additional imports sharing a dependency reuse the same initialized dependency instance. An edited file does not silently replace a live module. An identical repeated import/alias is idempotent; conflicting aliases and duplicate imports within one header retain ordinary diagnostics.
- R07 — Implement `:reload MODULE` for a REPL-owned module. Build that module and its reachable REPL-owned dependencies as a fresh graph; report the initializers that will rerun; switch subsequent namespace lookup only after successful construction. Existing selected bindings, values, and closures retain their old identities/graphs. Never reload, reconstruct, retarget, or migrate an application-owned root or its dependency graph.
- R08 — Preserve staged namespace publication and nontransactional effects. Compile/type/link failure executes no source and publishes no names. Runtime failure/cancellation publishes no staged declarations or aliases, while completed mutations, output, and valid escaped values remain. Initialization guards must distinguish valid initialized storage from JVM default/uninitialized fields.
- R09 — Introduce a trusted session/module registry whose job is locating actual typed storage, initialized instances, source revisions, and owned resources—not defending against hostile Java callers. Remove source-local-only admission and REPL-specific cross-artifact anti-forgery requirements once their replacement is operational. Exact physical JVM types, ordinary static semantics, and valid live instances still matter.
- R10 — Attached evaluation sees the actual application's public root declarations as current-module bindings. Ordinary assignment updates public `@mut` root fields/cells; immutable/public-redeclaration rules remain. Private root names and stack locals are not part of the evaluation namespace. Other-module imports retain normal Lyra mutation-ownership rules. No debug setter command or copied root state is allowed.
- R11 — Support typed callable/aggregate transfers between scratch code and the registered root/imported modules, including values stored in root state before a later failure. Normal AOT foreign-artifact/SAM behavior remains unchanged. The trusted REPL path does not need adversarial capability proofs, but must not coerce wrong signatures or physically incompatible generated classes.
- R12 — Preserve the existing synchronous, opening-thread-owned `LyraSession.open/submit/cancel/reset/close` API. Supply internal owner-executor composition for standalone console/managed use where needed, rather than silently changing existing methods to futures or moving existing callers' execution to another thread. Attached evaluation stays on the application's original owner thread.
- R13 — Implement cooperative application request servicing at opt-in generated function/call boundaries, self-tail-loop backedges, and executable-form boundaries, plus explicit Java host polling. Service one request and resume main. No nested evaluation, persistent debugger pause, forced thread termination, or evaluation on socket threads.
- R14 — Ctrl-C cancels an active instrumented evaluation and returns to a usable prompt; when editing, it discards only the unfinished buffer. API, remote cancellation, and disconnect use the same admitted operation identity/token. Evaluation cancellation must not cancel main or unrelated instances. Blocking external I/O may delay cancellation and must be reported truthfully.
- R15 — Use conservative generation retention instead of adding a fine-grained reachability/collection framework: standalone generations live until reset/close; attachment-generated code and its required storage may be retained by the application root until root close. Scratch reset removes names and aliases without invalidating values the application may still hold. Detach/closing the control service does not close an externally owned root.
- R16 — Replace the optional attachment protocol with an explicitly versioned localhost-only, no-authentication protocol. No token generation, credential files, authentication exchange, credential permissions, or authentication timing requirements remain. Listening is disabled unless explicitly enabled. Document that any process able to connect can execute code with the application's authority.
- R17 — Retain functional transport properties: one controller/workspace, finite framed messages, request identity, exact terminal status, revision consistency, cancellation, explicit reconnect/status lookup without source replay, and orderly shutdown. Basic parse/framing/resource bounds are reliability requirements, not a new hostile-peer security project.
- R18 — Provide `lyra attach ENDPOINT` with the needed plain/history/keymap console options and no `--token-file`. Replace token-oriented remote endpoint/options APIs and wire messages cleanly. Old remote clients must update; do not implement legacy authenticated mode, compatibility token shims, or silent authentication downgrade.
- R19 — Keep the essential commands `:help`, `:bindings`, `:type`, `:load`, `:reload`, `:reset`, `:history`, and `:quit`. `:type` and completion never execute code or publish names. Complete needed command/file/module/binding/type/accessor completion inside console tooling, without a public editor/LSP API or extra inspection commands.
- R20 — Preserve the existing local input coordinator/JLine program-input bridge and prove it with real generated `std->io` code. Source entry and program input cannot consume one another's bytes. Attached evaluation uses the host's stdin/stdout/stderr; process streams are not transported as socket output/input. Caller-owned streams remain open.
- R21 — Keep history in memory unless a path is explicitly supplied, never replay it, and keep program input out of source history. Security-only restrictive-permission/symlink policies are not completion requirements for trusted load/history files. Preserve normal UTF-8 validation, useful path errors, and non-destructive writes.
- R22 — Provide `run ROOT --repl`, `compile ROOT --repl`, and explicit Java embedding of a debug-capable root. Run enables the service for that run. Compile records capability but does not listen. Compiled activation uses `lyra.repl.enabled`, `lyra.repl.port`, and `lyra.repl.wait`; remove token properties. Keep literal application arguments and main's exit behavior unchanged.
- R23 — Complete debug-capable classes, thin JARs, and bundled runnable JARs. A bundled debug JAR must contain the actual production compiler/REPL/runtime closure needed for in-process compilation, but not CLI/JLine/tests. Normal artifacts remain free of REPL/compiler dependencies and generated request-service calls. Capability/dependency metadata serves compatibility and deterministic packaging, not a new signing/tamper-defense system.
- R24 — Start the opted-in listener before main without evaluating partially initialized modules. Optional wait-for-client occurs after successful initialization and before main. Main completion, initialization failure, and explicit shutdown close the control resources without keeping the process alive or changing application ownership.
- R25 — Retain exact canonical types, bounded snapshots, original source labels/URIs/document versions, and UTF-16 spans. Extend existing delayed callable source mapping to imported/reloaded modules and attached roots. Compiler metadata re-analysis is allowed; rerunning existing source initializers to reconstruct state is not.
- R26 — Update living specifications, decisions, docs, and the Phase 24 matrix to distinguish completed work, still-required implementation, and the user-approved removals. Final completion requires real passing evidence for every retained requirement, not merely changing BLOCKED to PASS or weakening tests.

## Settled Decisions

- D01 — Product scope: complete local console, local Java API, persistent imports, REPL-owned reload, and live application attachment. Only automatic local-root startup and the explicitly removed security work leave the accepted completion scope.
- D02 — Network: use loopback only, explicitly enabled, default ephemeral port, protocol version 2, no authentication or token files. Client/server versions must match; a version-1 peer receives a clear unsupported-version outcome, never a silent security downgrade.
- D03 — Remote migration: replace RemoteEndpoint with address and optional session identity, remove token/credential options and Authenticate/challenge messages, and change `lyra attach` to require only ENDPOINT plus optional console settings. Delete unused authentication code instead of retaining dead compatibility branches.
- D04 — Trusted linking: one owner-confined registry records real module instances and direct typed export/storage links. It validates existence, initialized state, ownership thread, lifetime, declaration/type consistency, and exact MethodTypes; it does not prove hostile caller resistance or require opaque cross-artifact capabilities as execution authorization.
- D05 — Compiler/runtime separation: immutable compiler module records carry logical ID, source revision, declaration/export contracts, dependency topology and semantic facts; runtime records carry actual initialized instances and exact bound accessors. Neither source metadata nor an empty module handle substitutes for the other. Retain existing sealed compiler correctness boundaries.
- D06 — Identity: distinguish logical module identity, revision/generation identity, compiler-local declaration/storage IDs, and display source origin. Pin live versions; allocate fresh compiler identities for fresh reload generations without changing old captures or diagnostics. Do not use matching names or numeric IDs as an excuse to link a different physical instance.
- D07 — Execution plan: each submission explicitly partitions NEW modules, REUSED initialized modules, the new scratch unit, and optional BORROWED application modules. Only NEW initializers and the new scratch entry execute. New cyclic function groups receive all state shells/links before any eager work; normal eager-cycle rejection remains.
- D08 — Import failure semantics: aliases/declarations publish only on successful submission. Successfully initialized dependency instances may remain in the private instance registry after a later submission failure and are reused on an explicit later import; they do not become visible bindings automatically. Failed/uninitialized modules are never reusable. A failed reload never promotes its provisional graph over the currently pinned graph.
- D09 — Reload: `:reload MODULE` reconstructs the selected REPL-owned reachable graph, using fresh source snapshots. It redirects future lookup through active namespace aliases only after success; already materialized selective bindings and captured values retain old versions. Application-owned graph nodes remain pinned and are never reconstructed.
- D10 — Resource simplification: standalone reset/close retires owned generations. Attachment scratch reset/close removes lookup state, but producer generations potentially reachable from application values are conservatively held by a root-lifetime resource group until root close. Separate lookup invalidation from producer invocation lifetime; a workspace reset must not poison a root-held closure.
- D11 — Ownership/API compatibility: retain synchronous owner-confined LyraSession as the core. Add only an internal owner runner for local consoles/managed composition and a narrow explicit root-attachment service for Java hosts. Do not replace the local API with a new generalized asynchronous framework.
- D12 — Cancellation: retain admission-time cancellation probing, one active request, and cooperative generated boundaries. Share the active evaluation token across scratch and application functions invoked from that evaluation. Application request-service points catch/control evaluation outcomes and resume main, rather than allowing cancellation to escape into main.
- D13 — Live application facts: initialize attachment from current public binding contracts and conservatively model mutable state changed by main/host activity. Compiler metadata reconstruction never means replaying initialization or assuming current values. Use existing symbolic unknown/parameter flow behavior where an exact current callable target is not known.
- D14 — Deployment: retain opt-in `--repl` capability and fixed JVM activation properties, with no token property. The optional service is a concrete REPL implementation, not a plugin system. Normal runtime/compiler dependencies stay unchanged. Debug bundles carry their actual production closure and required source snapshots; normal outputs retain existing defaults.
- D15 — File/console trust: use normal target-side filesystem access for :load/:reload and contextual path/module completion. Remote paths refer to the host application, not the client. Keep standard UTF-8/errors and source/program-input separation; do not add security-only no-symlink or restrictive-permission requirements.
- D16 — Completion evidence: split mixed Phase 24 rows into narrow requirement/evidence entries. Removed authentication/hardening and automatic local-root requirements are explicitly superseded/deferred; imports, trusted root linkage, cancellation, reload and deployment require executed PASS evidence. Never use passing console/protocol tests as substitutes for live application integration.

## Out of Scope

- Automatic `lyra repl ROOT_MODULE` initialization and a configured local root retained across scratch reset. Local optional positional input remains a source-search directory; live attached application-root support remains in scope.
- Token authentication, credential files, credential permission enforcement, auth challenge/timing/constant-time comparison, user authorization, REPL anti-forgery isolation, signed artifacts, additional hostile-peer security hardening, and security-driven load/history path restrictions. These are explicitly deferred, not unfinished completion blockers.
- Non-loopback listening, TLS/SSH server implementation, arbitrary PID/JVM injection and remote exposure beyond the approved localhost endpoint.
- Legacy authenticated remote protocol support, token-taking compatibility shims and simultaneous protocol-mode frameworks. The optional remote surface is replaced cleanly; ordinary local/AOT compatibility is still required.
- Fine-grained generation garbage collection, reference-counting frameworks, class-unloading guarantees, unlimited session memory, automatic source eviction, or a generalized workspace cache.
- Application graph reload/restart, state migration, retargeting old closures, latest-version handles, automatic replay or resubmission, automatic result bindings, and implicit std->io imports.
- Private/stack debugger inspection, breakpoints/stepping/watchpoints, persistent pause/resume, arbitrary host reflection/RPC, generic Java object/value handles, hostile-code sandboxing or forced cancellation.
- Off-thread incremental compilation, multiple simultaneous controlling workspaces, persistent serialized live state, remote stdin forwarding and process-output capture into the protocol.
- Editor/LSP/document management, structural Lisp editing, public completion APIs, AST/IR/disassembly browsers, timing/profiling/statistics commands and speculative plugin/backend frameworks.
- Changes to normal language mutation/type rules, normal AOT closure/SAM behavior, Java/engine/Vulkan interop, additional standard-library domains, alternate execution backends, or other previously deferred language features.
- Authentication removal does not put initialization correctness, type correctness, owner-thread execution, lifecycle validity, ordinary import ownership, functional message framing or correct cancellation out of scope. Those remain required for a working REPL.
