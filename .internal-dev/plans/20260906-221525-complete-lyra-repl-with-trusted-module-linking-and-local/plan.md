# Complete Lyra REPL with trusted module linking and localhost application attachment

## Feature

Finish the existing direct-Java-25-bytecode REPL rather than rebuild delivered foundations. Deliver the local plain/JLine console and compatible synchronous local Java evaluation API, persistent user-module imports including std->io, explicit REPL-owned module reload, and actual live application attachment through an explicitly enabled localhost listener. Cleanly replace the optional pre-release attachment API/CLI/protocol with credential-free v2. Use trusted exact typed links to explicitly registered module instances while preserving ordinary language/AOT contracts, actual storage/cell/function identity, initialization, owner-thread execution, producer lifetime and compiler semantic/IR consistency. The recorded planning baseline is ae793e7d6776f6611fa78ad80ea357ac827ed131; read-only validation confirmed that Git branch ref. Java 25.0.4/Maven 3.9.11/Linux are reported planning-environment facts, not freshly executed validation. The user explicitly confirmed the carried-forward scope, including imports, reload, actual application roots, debug deployment, localhost without authentication, trusted linking, clean optional remote replacement and no automatic local-root initialization. Local startup is empty with search directories and explicit imports/:load. Supersede conflicting REPL security/local-root-startup requirements explicitly, not ordinary language/AOT contracts. No repository edits or builds are authorized or performed by this planning review; implementation starts only after an execution instruction. No prior validator handoff was supplied.

## Required Behavior

- R01 — Protect delivered behavior: persistent scalars, arrays, tuples, callable summaries, higher-order calls, recursion, shared mutable cells, lexical replacement, typed snapshots, non-executing :type, delayed source mapping, plain/JLine editing and cancellation foundations. No interpreter, transcript replay, copied-value persistence or reduced REPL language. Existing source-local tests are regression gates, not proof of new module/attachment behavior.
- R02 — Source surface: finite ordinary submissions with a leading import header and new forms; :load UTF-8 files; user-module imports at any submission; std->io; aliases, selected imports and re-exports under existing language rules. Never call main automatically on import/:load, add implicit imports/results, retain unresolved declarations pending later input or retarget old lexical references. Local startup is empty. Positional repl directory is a search-directory convenience, supplemented by repeatable --source-root DIR, not an initialized local root.
- R03 — Pinned reuse: reuse a successfully initialized module instance for its pinned source revision across later submissions and transitive imports. Execute only new source and previously uninitialized requested dependencies. Resolve existing pins before rereading backing files; edits/deletions do not replace a pin or rerun an initializer. Distinguish logical module identity, canonical source identity, immutable source revision, producer declaration identity, runtime instance and graph-generation identity. Preserve resolution ambiguity, duplicate identity, SCC and eager-cycle diagnostics.
- R04 — Complete imported values: imported scalar/array/tuple/function exports and recursively callable-bearing aggregates work across submissions using original state and exact JVM types. Preserve import rebinding/aggregate-mutation restrictions through aliases, calls, projections and re-exports. Module functions may mutate their own state. Trusted linking neither makes imports writable scratch bindings nor changes ownership rules.
- R05 — Publication/effects: compile/type/link failure executes no Lyra source and publishes no namespace/default changes. Compiler/resolver filesystem reads and retained diagnostics are not source execution. Preflight the complete new graph and known resource/link requirements before initializers. Initialize new graphs and execute source under one admitted operation; commit names, aliases and defaults only on success. Runtime failure/cancellation preserves completed mutations/output and valid escaped values but not staged names. Track successfully initialized but unpublished resident modules separately from aliases. Reuse a resident only when its required initialization dependencies completed successfully. Retained failed/partial producers are not initialized residents; explicit retry may construct a fresh graph and reports actual attempted initializer reruns. Retention never authorizes reads of uninitialized storage.
- R06 — Reload: :reload MODULE accepts a namespace alias or logical module ID identifying a REPL-owned module and rejects absent, ambiguous or application-owned targets. Resolve the target's fresh source and recursively reconstruct its REPL-owned dependency closure, using the new import topology; stop at borrowed application-owned dependencies and retain their original transitive graph. Report scheduled, actually attempted and completed initializers distinctly, including failure/cancellation. Publish new defaults only after success. Future namespace lookup/new imports use new defaults; captured values/functions, selective imports, compiled lexical references and existing dependency edges keep their original producers. Unaffected defaults remain unchanged. No watcher, automatic/application reload, state migration or old-reference retargeting.
- R07 — Trusted model: remove token authentication, challenges, credential-file operations/permissions, constant-time credential comparison, hostile-client security campaigns and REPL anti-forgery obligations. Use direct typed links to explicitly registered real instances. Retain exact physical/logical type compatibility, compiler semantic/IR consistency, initialization flags, owner/lifetime checks and ordinary import semantics. Ordinary non-REPL artifact/closure authentication, compatibility validation and behavior remain unchanged.
- R08 — Attachment access: explicitly enabled loopback-only listener, port 0 by default; no token/credential file generated, read or required. Display the actual bound endpoint and explain that any process able to reach it can execute with application authority. One controlling connection/workspace and one active operation are coordination rules, not authentication. Validate configured addresses/ports and actual loopback binding, including supported IPv4/IPv6 forms. No sandbox or hostile-network claim.
- R09 — Actual root attachment: register an existing REPL-capable application's root on its owner thread. Public top-level exports enter current-root evaluation scope through actual typed accessors; ordinary count := value changes the real public @mut field, and public functions use the real graph. Preserve immutable/private/public-redeclaration/import rules, including re-export provenance; expose neither stack locals nor private names. Never clone or reinitialize the root. Java hosts use an explicit attachment entry point and owner polling. Arbitrary PID/JVM objects and uninstrumented roots are not retrofitted.
- R10 — Owner/cancellation and flow: execution, live reads/writes, snapshot extraction, publication, reload and lifecycle run on the owner. Preserve synchronous opening-thread-owned LyraSession semantics; managed CLI consoles use an internal single-owner loop without changing public submit result types. Attached applications keep their original owner. Opt-in function/call/form/self-tail-loop boundaries service at most one request, never dispatch nested evaluations and resume the app. Treat possible attachment mutations as explicit effect boundaries in attachable compiler analysis as well as subsequent evaluations: previously compiled application/session consumers must not retain unsound initializer-only callable, cell or aggregate-provenance facts after permitted external writes. Preserve required higher-order behavior and import ownership without guessing targets by signature. Ctrl-C/API/remote cancel/disconnect targets only its evaluation, never main or a JVM thread. Blocking host I/O/owner compilation may delay completion; status is truthful and control publication remains responsive.
- R11 — Lifetime: separate namespace visibility from code/storage lifetime. Standalone sessions conservatively retain successful/attempted generations and old reload graphs until reset/close. Attachments pin producers, original link tables, structural type domain, required semantic summaries and source data to the externally owned root lifetime, including valid values stored before failure/cancellation. Reset removes scratch names/aliases/history view but preserves root state and root-held values. Disconnect preserves workspace. Detach/service close closes control resources, not the root or root-held closures. Reopening a service on the same live root reuses its retained type/producer domain without reviving removed scratch names; reject simultaneous duplicate service ownership rather than establish incompatible domains. Root close retires dependent producers. No precise heap collector, forced unloading or bounded-total-metaspace guarantee.
- R12 — Sources/results/limits: compiler IDs remain separate from caller labels/URIs/versions/UTF-16 offsets; old/reloaded revisions coexist. Delayed imported/reloaded/root/session failures map to actual producer source. Keep immutable bounded snapshots without user-code execution, preserving unsigned values, nil/Unit, aliases, Unicode and explicit truncation. Preflight source-retention capacity for the complete newly discovered graph, reload revisions and required root context, not only the submission; never evict source needed by a live producer. Preflight known result-type/minimum-envelope representability and encoded LOAD payload limits. Runtime-dependent display size is handled by existing bounded truncation, not an impossible promise to predict every result before execution. Keep UTF-16 character limits distinct from encoded UTF-8/JSON frame bytes. Bounded diagnostic/query/result envelopes must remain deliverable after effects without turning transport truncation into rollback or reexecution.
- R13 — Essential console: exactly :help, :bindings, :type, :load, :reload MODULE, :reset, :history, :quit. :type analyzes supplied source against committed context without execution, pinning or publication. Semantic completion uses committed binding/type/member metadata only; file and discoverable-module completion may perform bounded read-only execution-host filesystem/configuration lookup without compiling, initializing or pinning candidates. Display final expression values and committed declaration names/types, with no result aliases. Retain multiline completeness/invalid recovery, bracketed-paste atomicity, indentation, highlighting, delimiter matching, Emacs/vi, history search/navigation, resize, cleanup and plain fallback. This is console tooling, not a public editor/document/completion service.
- R14 — Paths/I/O: local :load uses local paths; attached :load/:reload, path/module completion and discovery use the application's server filesystem/source roots. Never read attached load paths on the client. Optional-console paths follow normal filesystem semantics instead of mandatory permission/symlink security policy; retain regular-file/I/O/UTF-8 validation, canonical module resolution, explicit history opt-in and reliable writes. One local input owner coordinates source and generated readLine. Attached std->io remains on host stdin/stdout/stderr, never socket-forwarded. Program input never becomes source/history and caller streams remain open.
- R15 — Remote v2: replace optional endpoint/options/CLI/protocol/API and tests cleanly; no legacy authenticated mode or token adapters. V1 peers receive unsupported-version/upgrade errors rather than silent bypass. Retain length-prefixed UTF-8 JSON, explicit schemas, session/request identity, revision and mutation-sequence coordination, finite frames/queues/result retention, controller admission, terminal results/status/cancel/reset/query and explicit reconnect without replay. Add bounded owner-dispatched LOAD, RELOAD and console completion. Use mutation sequence together with revision for wire freshness, including reset, which does not change the established local revision contract. Correlate late replies and cancellation to request/controller identities; stale or disconnected controllers cannot cancel a later request. Duplicates are recognized without reexecution, mismatched duplicate payloads rejected, and unavailable retained results reported explicitly.
- R16 — Deployment: run ROOT --repl, compile ROOT --repl, explicit run port/wait options and Java embedding. Compilation only records capability and never listens. Compiled applications require lyra.repl.enabled, with optional lyra.repl.port and lyra.repl.wait; remove token properties/options. Bootstrap control can listen before root construction/main, but live requests are gated until initialization and registration complete. Optional wait occurs after initialization and before main, ending on controller readiness or orderly shutdown, without exposing partial root state. Initialization/main failure and normal completion close control resources and preserve normal exit/arguments; no post-main keepalive.
- R17 — Artifacts: REPL-capable classes/thin/bundled JARs have explicit compatible metadata and actual required production dependency closure. Normal AOT artifacts need no compiler/REPL/JLine distribution and contain no generated optional polling calls. Debug bundles exclude CLI/JLine/tests/credential material. Preserve normal metadata compatibility and deterministic output. Debug profile includes original reachable source snapshots, canonical source/logical-module/import resolution inventory and reproducible scalar compilation options, sufficient to reconstruct semantic facts without live resolver objects, serialized IR or initialization replay. Disclose debug source inclusion; ordinary include-sources behavior remains unchanged.
- R18 — Honest completion: reconcile living specs, decisions, README/AGENTS, examples, exact method coverage and Phase24. Superseded authentication/security/local-root-init work is explicitly classified, not falsely implemented or left as an unexplained blocker. Every retained import/reload/lifetime/input/attachment/deployment requirement has executed evidence. Preserve four modules and Phase23 methodology/thresholds. No UNAVAILABLE stub, placeholder, weakened test, skipped phase or unacknowledged in-scope defect qualifies as completion.

## Settled Decisions

- D01 — Empty local REPL with explicit file/import workflow. repl [DIR] and repeatable --source-root configure search directories. Automatic local-root initialization is deferred; actual application-root attachment remains required.
- D02 — Explicit no-auth loopback listener, default port 0. Attach syntax has no token-file argument; remove token/challenge/credential state, terminology and authentication-only tests. Print actual endpoint and authority warning.
- D03 — Remote v2 clean replacement: RemoteEndpoint contains address and optional sessionId. V1 gets an upgrade diagnostic. No silent downgrade, ignored token flags, fake credentials or second authenticated mode.
- D04 — Compiler immutable module/flow data describes producer relationships; runtime exact typed links bind real storage. Validate correct type/instance/lifetime and ordinary semantics, not hostile Java caller unforgeability.
- D05 — Explicit new/reused link plan: allocate/link/init only new module/SCC shells; new-to-new imports may use typed state fields and reused imports exact storage/export links. Do not cast unrelated state classes or instantiate another graph for a view. Preflight all linking before source effects.
- D06 — Qualify retained facts by source revision/producer/graph generation while preserving logical names and display origins. Pinned identities stay stable; reload allocates fresh identities. Distinct retained revisions never merge into one ModuleId-keyed executable graph or by binary-name equality.
- D07 — Structural domain lifetime follows executable values: standalone workspace until reset/close, attached root until root close. Anchor to actual root Java package and tuple/function Class identities, extending that same domain for new structures and later service reopening. State/cell/closure/facade classes remain generation-local. No value copying/wrapping to mask loader mismatch.
- D08 — Keep canonical flow/IR sealing and ordinary AOT authentication. Extend producer-backed mutable-state/ownership facts through both evaluations and attachable application effect boundaries. Remove source-local runtime policy only after complete graph linkage and required callable behavior are proven.
- D09 — Distinct visible defaults/aliases, initialized residents and retained attempted producers. Reuse successfully initialized unpublished modules only when required dependencies are valid. Scratch reset cannot invalidate root-held links or type/source context.
- D10 — Reload fresh REPL-owned reachable graph using fresh source topology, stopping at borrowed app graphs. Publish all affected defaults atomically after success; aliases consulted by future namespace lookup follow defaults, while compiled/captured/selective references remain producer-bound. Identical repeated imports are idempotent; conflicts remain errors. Report actual initializer progress, not planned work as completed reruns.
- D11 — Preserve synchronous local API. Managed consoles use one internal owner executor; attached execution stays on app owner. Compile/type/reload/query run under owner admission; transport status/cancel use safely published immutable control state. No speculative compiler or general executor API.
- D12 — One scoped evaluation context owns cancellation. Application boundaries dispatch at most one idle request; evaluation boundaries only check that request token. Explicit owner-dispatched evaluation reuses its admitted lease. Contain expected evaluation cancellation/failure before main resumes, clear contexts in finally, and never attach producer lifetime to the lease.
- D13 — Reuse ConsoleInputCoordinator/JLine programInput and exact RuntimeIoEnvironment; add actual compiled std->io tests. Host I/O remains at host, one input owner, no source/input history mixing.
- D14 — Target-side LOAD/RELOAD and path/module completion. Read a load file once into exact text plus file URI, preflight encoded source/envelope and graph-retention capacity before execution, then compile that same text. Return bounded source-only history information. Semantic completion reads committed metadata; filesystem completion is read-only and never pins/initializes.
- D15 — Versioned debug metadata and original-source reconstruction preserve schema-1 normal compatibility. Embed canonical resolution topology and reproducible options, not live SourceResolver objects or serialized AST/semantic graph/IR. Reconstruct analysis without effects or edited original files. Keep normal include-sources unchanged.
- D16 — Fixed optional application/bootstrap composition in lyra-repl with dependency-free runtime hooks. Debug packaging collects only known production compiler/REPL/runtime classes/resources; missing dependencies are actionable packaging errors. No reverse Maven dependency or incomplete bundle.
- D17 — run/compile --repl and enabled/port/wait runtime controls. Compile never listens. Bootstrap listener is distinct from registration of an OPEN root; gate live work until initialization/registration, wait only before main, preserve literal app args/exits and close control at main completion without keepalive.
- D18 — Current-scope method-level Phase24 PASS gates completion. Only explicitly approved security/local-root obligations are superseded/deferred; imports, reload, escaped values, I/O, polling and all artifact modes require fresh evidence.
- D19 — Operational bounds preserve existing result semantics: reserve all known graph sources and minimum encoded envelopes before effects; dynamically truncate snapshots/diagnostics/query lists explicitly within finite limits. Wire freshness uses revision plus mutation sequence so reset remains detectable without breaking local API revision semantics.
