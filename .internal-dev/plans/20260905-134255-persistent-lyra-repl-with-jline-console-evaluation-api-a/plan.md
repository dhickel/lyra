# Persistent Lyra REPL with JLine console, evaluation API, and opt-in application attachment

## Feature

Implement a persistent, direct-bytecode Lyra REPL that feels like writing ordinary Lyra code. Deliver a rich JLine console, a small headless Java evaluation API, and an authenticated loopback socket server/client for opt-in debug-enabled applications. Submissions execute once against live state, preserve lexical binding and closure semantics, and can use ordinary assignment on mutable bindings. An attached workspace enters only the root module's public top-level scope: public @mut bindings can be assigned with ordinary `name := value`, while private names, stack locals, and mutation of other imported modules remain unavailable. Keep future editor integration possible through source-origin-aware evaluation requests and transport-independent session execution, without implementing an editor, document service, LSP, structural editing, or a general debugger.

## Required Behavior

- Deliver all three selected surfaces now: local console, public Java session/evaluation API, and socket attachment to running debug-enabled Lyra applications. This is implementation planning only; no project modifications or build execution were performed during the interview.
- Use the existing Java 25 compiler, sealed semantic/typed-IR pipeline, and Class-File API execution path. A production interpreter, transcript re-execution after each input, or independent simplified language implementation is not acceptable.
- Persist actual bindings, mutable cells, arrays, tuples, function values, imported module instances, and their identities across submissions. Execute only newly submitted forms and newly requested module initializers. Earlier effects must not rerun implicitly.
- Preserve lexical replacement: a later private let creates a new binding identity, possibly with a different type; earlier references and closures keep the old binding. Existing @pub names cannot be redeclared. Cross-submission @mut assignment updates the original storage and captured shared cells.
- Accept expressions, assignments, declarations, and a leading import header per submission. A submission may contain multiple forms. Preserve normal typing, source order, modifiers, complete function signatures, and mutual recursion within that submission. Reject unresolved references rather than keeping pending definitions for future submissions. Do not add implicit imports or implicit result bindings.
- Compile/type/link failures execute nothing and publish no names. Commit a submission's new names/import aliases only after successful execution. On runtime failure or cancellation, publish no new names but retain completed mutations, output, and other effects; do not claim rollback. Keep the session usable, and preserve valid values/closures that escaped through completed effects without exposing uninitialized storage.
- Reuse initialized imported module revisions. Permit additional imports in later submissions. `:load PATH` submits the file's UTF-8 contents once with file source mapping; it does not call main automatically or become automatic source replay.
- Provide explicit `:reload MODULE` for REPL-owned modules. Reconstruct that module's REPL-owned reachable dependency graph, report which initializers are being rerun, and publish the new graph only after successful construction. New references use the fresh graph; existing bindings and closures retain the old graph. Never reconstruct, replace, retarget, or migrate the running application's graph.
- Provide `lyra repl` for an empty workspace and `lyra repl ROOT` for initialization of a source root and entry into its public top-level scope without invoking main. Support configured source roots using existing resolution rules. Keep ordinary no-argument CLI usage and existing run/compile behavior unchanged.
- Provide `lyra run ROOT --repl` and `lyra compile ROOT --repl` opt-ins, plus a Java embedding entry point. The run option enables instrumentation and a listener for that run. The compile option builds debug capability but does not enable listening by itself. A compiled application requires an explicit runtime property to activate its listener.
- Support debug-enabled classes, thin JARs, and bundled runnable JARs. A debug-enabled bundled JAR includes the actual compiler/REPL dependency closure needed for in-process source compilation, but not JLine/CLI. Thin/classes output records and documents required external dependencies. Normal artifacts remain free of compiler/REPL-server/JLine dependencies and generated safe-point calls.
- Activate the listener before main, but prohibit evaluation against partially initialized application modules. Start main normally by default; support an explicit wait-for-client startup option after successful initialization and before main. Normal main completion closes REPL resources and preserves the application's exit request; attachment must not keep the process alive afterward.
- Run all live application reads, writes, evaluation, value formatting, and lifecycle operations on the module owner thread. Compiler-inserted cooperative safe points service debug requests at function/call boundaries, direct self-tail-loop backedges, and appropriate executable-form boundaries. Java hosts can explicitly poll on the owning thread. Evaluate one request, then resume the app automatically; no persistent pause/resume debugger mode.
- Attached evaluation sees root public exports as current-module bindings, not as ordinary read-only imports. Thus `count := 10` is legal for a root public @mut count without a special debug setter command. Immutable exports remain immutable; public names remain non-redefinable; ordinary imports of other modules retain existing read-only mutation rules. Keep this authority confined to the explicitly attached root context.
- Support cooperative cancellation by Ctrl-C, API request, remote cancel, and remote disconnect. Cancellation unwinds only the active REPL evaluation at safe points and restores app execution; it does not terminate the host, poison unrelated module instances, or cancel main. Clear an unfinished console buffer on Ctrl-C when no evaluation is active.
- Use a single persistent workspace and at most one authenticated controlling connection per attached application. Reject concurrent controllers. Disconnect requests cancellation of active evaluation, preserves committed workspace state, and never resets/closes the application. Reconnect exposes session identity, current status, and retained terminal results without automatically rerunning uncertain requests.
- Bind TCP only to loopback, defaulting to an ephemeral port. Require a cryptographically random high-entropy token. Store generated tokens in restrictive, exclusively created files; print endpoint and credential-file path rather than the token. Support SSH tunneling for remote-machine access. Do not implement LAN listeners, built-in TLS, PID injection, or unauthenticated attachment.
- Use a versioned bounded JSON-over-socket protocol with explicit framing, authentication/handshake, request identity, session revision, terminal evaluation statuses, cancellation, reset, and the internal console-query operations needed by the attached console. No Java object serialization, arbitrary reflection RPC, or generic host-object access.
- Preserve process/application std->io. Remote evaluation output goes to the application's stdout/stderr, and readLine consumes application stdin, not the network client. The socket returns evaluation results, diagnostics, and control statuses, not captured process output. Local console source reading and runtime stdin must share one coordinated input boundary so they cannot steal each other's bytes; runtime input must not enter source history.
- Provide rich JLine editing: grammar-aware multiline continuation, bracketed paste, sensible indentation, syntax highlighting, delimiter matching, contextual completion, Emacs default and selectable vi keymaps, history navigation/search, terminal resize handling, and a plain-terminal/non-TTY fallback. Do not add structural Lisp editing commands such as slurp/barf.
- Keep development commands to the selected essential set: `:help`, `:bindings`, `:type`, `:load`, `:reload`, `:reset`, `:history`, and `:quit`. `:type` determines type without evaluation. Include command/file/module/binding/type/accessible-member completion as applicable. Do not add AST/IR/disassembly browsers, timing/profiling, documentation/source browsers, automatic replay, or session statistics commands.
- Print successful final expression values with exact Lyra types and bounded escaped formatting. A declaration reports its binding/type without implicitly retaining a separate expression result; Unit-only/no-op submissions need no value line. Do not generate resN names or a last-result alias.
- Return immutable typed value snapshots through the evaluation API: exact canonical type, structured bounded scalar/aggregate display data, and explicit truncation/reference descriptions. Functions are descriptive values, not executable Java handles. Preserve unsigned mathematical values, nil/Unit distinctions, UTF-16 content, aggregate ordering, and function/array alias descriptions without evaluating user code for formatting.
- Keep the public API focused on opening an evaluation session, submitting source, receiving structured results/diagnostics, cancelling, resetting, and closing. Requests support a caller source label/URI plus optional document version and origin offsets for later editor selections. Do not publish completion, managed-document, document-edit, generic value-handle, or LSP APIs.
- Default to in-memory source history. Only an explicit history option/path enables bounded disk persistence. Exclude tokens, authentication messages, program stdin, and protocol traffic; never replay history at startup. Separate local/project/remote histories and expose read-only history listing, not replay commands.
- Preserve compiler diagnostic codes and source-mapped runtime failures, adding narrowly scoped REPL/configuration/cancellation statuses where needed. Retain submitted source text and exact UTF-16 source offsets so errors and earlier closures point to their originating submission/file, not generated wrapper code.
- Make reset explicit workspace reset, not application rollback: clear REPL-local definitions/import aliases/history view and retire their resources, but keep a configured/attached root and all completed root mutations intact. An empty-root session resets to an empty environment. Preserve generations still reachable through values stored in the root; close all workspace-owned roots/generations at final local shutdown and never close an externally owned application root on detach/reset.
- Require Linux terminal/PTY and subprocess validation plus platform-neutral API/compiler/protocol tests. Keep launchers and terminal provider selection portable; identify native macOS/Windows checks as unvalidated unless actually executed.

## Constraints

- Preserve the substantial existing dirty/untracked backend work. Planning baseline HEAD is a16a46b71780206c6cec27ee87adef29e5333069; implementation must inspect its then-current worktree and must not reset, discard, or silently attribute unrelated files to this job.
- Code is the implemented baseline; the top-level guide's frontend-only description is stale. Current specifications intentionally describe whole-graph compilation, thread confinement, artifact-local closure authentication, read-only cross-module imports, and non-retargeting reload. Extend only the explicitly authorized REPL profile and document the distinction.
- Do not bypass canonical semantic-flow analysis, graph certification, IR validation, definite initialization, mutation ownership, nilability, or exact type/ABI checks to make snippets compile. External live state must be modeled conservatively where current facts are unknown, not assumed equal to its original initializer.
- Do not compile each submission into an unrelated artifact and copy generic values to simulate persistence. Preserve typed storage, shared cells, arrays, closure authority and generated JVM type identity through an explicit session linking domain.
- Keep compiler-generated ordinary hot calls typed and primitive-specialized. Boxing and bounded reflective inspection are permitted only at the tooling/result boundary, not as a replacement execution ABI.
- Do not globally relax closure authentication or allow arbitrary Java SAM callbacks. Any bridging between an attached artifact and its session must be explicitly authenticated, exact-signature, owner/lifecycle checked, and restricted to that registered attachment.
- No network/JLine/compiler dependencies in lyra-runtime. Add only the narrow runtime control/linkage hooks required by this feature. JLine belongs to the console, and the optional REPL distribution owns compiler/socket dependencies.
- Cancellation is cooperative, not forced termination, process isolation, a CPU quota, or a sandbox. Do not use Thread.stop or terminate a host application. Native/blocking host I/O may delay a safe point; report busy/cancellation-requested truthfully rather than promising a deadline.
- Do not service nested evaluations while executing a REPL request or application initialization. A safe point is a cooperative scheduling boundary, not a guarantee that application invariants form a transaction.
- Completed effects survive failed evaluations/reloads. Do not close or invalidate a new generation merely because its namespace commit failed if a valid value from it escaped into retained state. Conversely, never expose JVM default values from uninitialized declaration storage.
- Old lexical bindings/revisions may keep classes and values alive. Reset/close must release owned references correctly, but JVM class unloading and bounded total heap/metaspace are not guaranteed. Do not invalidate application-held values to manufacture a memory-reclamation claim.
- Preserve normal source-root deduplication/ambiguity behavior, UTF-8 decoding, UTF-16 authoritative spans, canonical type signatures, deterministic packaging, source maps, and correct main/exit behavior.
- No runtime property/token/listening port or wall-clock value may enter deterministic compiled artifacts. Generated debug capability and artifact compatibility metadata are build inputs; live listener credentials/endpoints are runtime state.
- No network request or console command may bypass @mut, static typing, normal imported-module mutation ownership, or root-public-only visibility. Do not implement :set or an equivalent separate debug mutation API.
- No generalized plugin architecture, public backend SPI, managed document store, full incremental project cache, or framework for speculative editor features. Add only current evaluation/session/remote interfaces.
- Linux is the current validation environment with Java 25.0.4 and Maven 3.9.11. Do not claim native macOS/Windows validation without those environments. No test suite was run during read-only planning.

## Assumptions

- The REPL runs trusted owner-controlled code. Authentication protects access to an extremely privileged code-execution interface; it does not make submitted code safe or sandboxed.
- The user's later clarification supersedes the proposed separate debug setter: assignments must be ordinary Lyra code. The subsequently confirmed boundary is root public names only, with normal mutation rules outside that root context.
- The user retained console/API/remote delivery scope and explicitly authorized the planner to settle remaining details in best faith without further questionnaires.
- A finite submission is the unit of compilation and namespace commit. Users submit mutually recursive declarations together; the system does not accumulate unresolved pending definitions.
- For a configured local root, reset behaves like attached reset: it clears the scratch workspace while retaining that root's current state. Only an explicit new root/session or module reload reconstructs owned module state; reset never claims application rollback.
- Repeated identical imports of an already pinned module/alias may be treated as idempotent across submissions; conflicting aliases and within-header duplicates remain diagnostics. Explicit reload updates the affected module namespace for subsequent resolution, not previously captured/selectively imported value identities.
- Paths in an attached console's :load/:reload refer to the server application's filesystem and configured source roots. Tokens/history belong to the client where applicable. A future editor can submit source text with origin data instead of relying on remote file access.
- Local and remote consoles provide the same language and essential-command behavior, except that remote standard I/O remains at the application process and history persistence is client-controlled.
- Unrequested evaluation timeouts, automatic restart, automatic replay, automatic reconnection with resubmission, post-main process keepalive, and persistent disk session state are excluded. Reconnection may be explicit through the attach command.
- JLine 4.0.0 is a verified available baseline: upstream documents Java 11+ and a Java 22+ FFM provider, and Maven Central supplies the 4.0.0 reader artifact. The project remains a Java 25 classpath build; adding JPMS is unnecessary.

## Settled Decisions

- Architecture: introduce one optional lyra-repl module containing the reusable engine/API and small socket implementation; put JLine adapters in lyra-cli. Keep compiler session integration inside lyra-compiler and dependency-free lifecycle/control primitives inside lyra-runtime.
- Use immutable session compilation inputs and complete validated submission artifacts. Represent existing bindings/module instances as real typed external storage with persistent declaration identities and revision-qualified linkage. Generate only new executable work, though compiler metadata analysis may revisit relevant prior definitions.
- Maintain a session JVM type/linkage table that reuses exact function/tuple/cell types and an explicit authenticated loading domain. For attachment, reuse compatible existing artifact types and exact public facade accessors; do not clone the application's state or invent a parallel untyped value runtime.
- Use a staged namespace commit plus nontransactional effects. Successful execution commits new definitions/import visibility; runtime failure/cancellation discards the pending namespace but preserves completed effects and necessary generation reachability. Initialization checks must remain meaningful for values escaping a failed submission.
- Keep lexical replacement and ordinary code assignment. Attach a root public binding as owned storage in the explicit root evaluation context; use its generated typed setter for @mut rebinding, and preserve normal array/function mutation behavior and other-module restrictions.
- Use one explicit owner executor for standalone sessions. Application attachment keeps the existing owner thread and services requests through opt-in compiler safe points or host polling. Compilation can occur over an immutable snapshot off-thread, but admission/commit is revision-checked and all live access stays on the owner.
- Permit one active mutating/evaluation operation per workspace; additional ones receive a stable busy response rather than building an unbounded queue. Cancellation/status remain responsive. Read-only console queries use committed metadata or owner-thread snapshots and never inspect live objects concurrently.
- Add `lyra repl [ROOT] [--source-root DIR]* [--history PATH] [--keymap emacs|vi] [--plain]` and `lyra attach ENDPOINT --token-file PATH` with appropriate console options. Preserve missing-command usage and existing commands. Keep colon commands outside the Lyra grammar and recognize them only as top-level console input, not inside strings/comments/forms.
- Expose `--repl` on compile and run. Use explicit run-side port/token-file/wait options and compiled-app JVM properties such as `lyra.repl.enabled`, `lyra.repl.port`, `lyra.repl.tokenFile`, and `lyra.repl.wait`; do not consume application arguments in generated launchers. Default port 0 and disabled compiled-app listener.
- Use a length-prefixed UTF-8 JSON protocol with a versioned handshake and explicit operation schemas. Bound frames to 1 MiB and bound authentication time, outstanding control work and retained terminal results. Use monotonic per-session mutation sequence IDs plus correlation IDs so duplicate/expired requests cannot be silently executed twice. Reconnect never automatically resubmits source.
- Use at least 256 bits of random token entropy, owner-restricted credential files, loopback-only endpoint validation, and constant-time credential comparison. Reject invalid versions/authentication/oversized or malformed frames before compiler work. Close slow/invalid peers rather than blocking application shutdown.
- Return typed bounded snapshots, not Java objects/handles. Default formatting budgets are depth 6, at most 100 aggregate elements per displayed aggregate, and at most 16 KiB total rendered result; encode truncation explicitly and escape controls/unpaired UTF-16 surrogates safely. Format unsigned values mathematically and functions by type/identity description without invoking them.
- The minimal public Java API supports session creation, source submission returning a completion/result object, cancellation by evaluation identity, reset and close. Results distinguish success, compilation failure, runtime failure, cancellation, busy and closed state and carry structured diagnostics/value snapshots. Optional source-origin metadata is a passive mapping, not a managed editor-document API.
- The console's :type operation checks without executing; :bindings lists accessible committed bindings and types using bounded rendering. No automatic result bindings, source replay, or implicit std->io imports. :history is inspection/navigation only, with optional bounded history-file persistence and no program-input recording.
- In TTY mode, Enter submits syntactically complete source and continues genuinely incomplete source; complete invalid source produces a diagnostic rather than trapping the user in continuation mode. Bracketed paste is treated as one submission. Plain mode uses the same completeness rules without prompts/ANSI on piped input. EOF on an incomplete unit reports an error; Ctrl-D on an empty interactive buffer exits.
- For local stdin, coordinate source entry and Lyra readLine through the same console input owner, switching out source completion/highlighting/history for program input. For attached evaluation, retain host streams without global System.setIn/System.setOut changes or remote capture. Cooperatively cancellable input adapters must not close caller-owned streams or steal another consumer's buffered data.
- Normal interactive quit returns success after recoverable evaluation errors. Plain/non-TTY mode continues through completed submissions, remembers evaluation failures, and returns 1 if any occurred; usage/startup/infrastructure failures return 2. Explicit remote detach/quit returns 0 after orderly cancellation, while protocol/connection failure returns 2. Existing run/main exit behavior is unchanged.
- Extend metadata/profile validation explicitly for debug-enabled dependency inventories and session linkage rather than relaxing strict artifact preflight. Record required runtime/compiler/REPL versions and actual preview requirements. Keep bundled debug assembly canonical and exclude test classes, terminal providers and credential material.
- At reset/detach, retire scratch bindings and cancel owned work without closing an externally owned root. Generation/resource ownership must account for closures or arrays stored back into root state. At application close, invalidate root-dependent session values and close the control service; no socket thread should keep the JVM alive.

## Validation Criteria

Arrays retain identity/aliases across submissions. Tuple/function types and higher-order calls work across generations, not merely scalar copies.
- Compilation errors, invalid imports and type failures publish nothing and perform no effects. Runtime failure/cancellation hides all newly staged names while preserving earlier effects. A valid closure stored in pre-existing mutable state before a later failure remains correctly linked; any uninitialized dependency fails structurally rather than exposing default storage.
- The full normative core remains executable in submissions: nilability, exact numeric types and unsigned display, checked arithmetic, conditionals/coalescing, arrays/tuples, callable and direct calls, explicit conversions, std->io and mutation rules. No reduced REPL grammar or evaluator substitutes for bytecode.
- Imports after earlier submissions work without rerunning previously initialized dependencies. Duplicate/missing resolution remains diagnostic. Explicit reload rebuilds only the requested REPL-owned fresh graph, reports repeated initializers, makes new lookup use the new revision and preserves old closures/references. Attempts to reload app modules fail without app changes.
- Public root attachment proves ordinary `count := newValue` changes the live application's public @mut count and its normal code observes that change. Immutable/private/nonexistent names reject access appropriately. Other-module imported bindings remain nonassignable. Public functions operate on the same module instances, not copies.
- Assignment/passing of Lyra-created function values across the explicitly attached session/root boundary succeeds only for exact compatible contracts, with valid lifecycle and owner checks. Wrong-thread access, arbitrary Java SAMs, unrelated artifacts and post-close values remain rejected in normal and REPL paths.
- All source execution and live inspection for an attached app occurs on its original owner thread. A busy tail-recursive app reaches a safe point, evaluates one request and resumes; nested requests are not dispatched. Initialization is never exposed partially.
- Ctrl-C/API/remote cancellation stops instrumented infinite REPL recursion and returns to a usable session. Cancellation during an application-function call invoked by the REPL does not abort main. Disconnect requests cancellation and preserves state. Delayed cancellation in genuinely blocking host I/O is reported accurately; no test depends on unsafe thread termination.
- The local console never consumes program readLine input as source or vice versa. Runtime input is absent from history. Attached evaluation stdout/stderr remains in captured host process streams, not remote result payloads, and input is consumed only from the host input stream. Caller streams remain open after session close.

Large/deep/aliased values terminate within budgets with explicit truncation/reference markers; formatting does not execute user functions or expose private state.
