# Artifacts and Java API

`lyra-compiler` compiles complete reachable source graphs to direct Java 25 bytecode. `lyra-runtime` validates, loads, instantiates, and closes those artifacts. Compiler-private semantic graphs, typed IR, flow proofs, and provenance are not public formats or extension APIs.

## Modules and Maven coordinates

| Module | Coordinate and boundary |
| --- | --- |
| Runtime | `io.mindspice:lyra-runtime:0.1.0`; values, metadata, loading, lifecycle, I/O, launcher |
| Compiler | `io.mindspice:lyra-compiler:0.1.0`; source resolution through Java 25 Class-File API emission and packaging |
| REPL | `io.mindspice:lyra-repl:0.1.0`; optional persistent sessions and protocol v2 |
| CLI | `io.mindspice:lyra-cli:0.1.0`; commands and console adapters |
| Editor | `io.mindspice:lyra-editor:0.1.0`; optional JavaFX workspace |

## Output forms

| Form | Contents | Launch/use |
| --- | --- | --- |
| Classes | Generated classes plus `META-INF/lyra/artifact.json`, `debug-map.json`, and optional sources | Add output and compatible runtime to a class path |
| Thin JAR | Same generated bytecode and metadata | Use with compatible external runtime; not promised as `java -jar` |
| Bundled JAR | Generated bytecode, metadata, runtime, and launcher | `java -jar`; exact public `main` required |

Debug-capable output has a separately declared `replCapability`, embedded source/resolution context, and required compiler/REPL/runtime closure. Ordinary output contains no REPL polling or compiler/JLine dependency.

Artifacts are deterministic for identical source snapshots and options. Class and metadata ordering, JAR entry ordering, timestamps, manifests, and JSON encoding are canonical. Absolute paths and wall-clock values are excluded. Publication uses a sibling staging target and atomic replacement.

Metadata records language contract, compiler build/version, runtime ABI, Java target, preview requirement, artifact and module revisions, exports and JVM descriptors, Java name mappings, source/debug hashes, and packaging. Nominal declarations use artifact schema 2; artifacts without nominal schemas retain schema 1. Metadata is compatibility data, not a signature or serialized IR.

## JVM type mapping

| Lyra | Java/JVM boundary |
| --- | --- |
| `I8`, `U8` | `byte` |
| `I16`, `U16` | `short` |
| `I32`, `U32` | `int` |
| `I64`, `U64` | `long` |
| `F32`, `F64` | `float`, `double` |
| `Bool`, `Char`, `String` | `boolean`, `char`, `java.lang.String` |
| function return `Unit` | `void` |
| value-position `Unit` | `LyraUnit.INSTANCE` |
| `@nil` primitive | Corresponding nullable wrapper at Java-visible boundaries |
| `Array<T>` | Exact primitive or reference JVM array |
| `Range<T>` | `LyraRange` with signed-long components and width tag |
| `Tuple<...>` | Deterministic immutable generated final class |
| `Fn<...;...>` | Deterministic typed generated functional interface |
| struct/class | Deterministic final generated reference class |

Unsigned values use same-width raw primitive bits; metadata preserves unsigned meaning. Java receives live arrays, not copies.

## Compile and load

```java
import io.mindspice.lyra.compiler.api.*;
import io.mindspice.lyra.runtime.*;

String source = "let @pub add :Fn<I32,I32;I32> = (=> |a b| (+ a b))";
CompileResult result = LyraCompiler.compile(
        CompileRequest.source("main.lyra", source));

if (result instanceof CompileResult.Failure failure) {
    failure.diagnostics().forEach(System.err::println);
} else {
    CompiledArtifact artifact = ((CompileResult.Success) result).artifact();
    try (LoadedArtifact loaded = LyraRuntime.load(artifact);
         ModuleHandle module = loaded.instantiate()) {
        ExportHandle add = module.export("add", "Fn<I32,I32;I32>");
        int value = (int) add.methodHandle().invokeExact(4, 5);
    }
}
```

The source request can instead use one path root, one logical module root, or a `SourceResolver`. It accepts repeatable source roots/resolvers, Java base package, Java target, preview, source embedding, semantic options, and compile/debug profile. Exactly one root is required. Expected source/configuration failures return `CompileResult.Failure`; no artifact exists.

`CompiledArtifact.writeClasses(path, options)` and `writeJar(path, JarMode.THIN_JAR or BUNDLED_JAR, options)` publish output. `WriteOptions.defaults()` refuses replacement; `new WriteOptions(true)` permits it.

## Generated facades

Each module has a deterministic instantiable facade. The exact generated Java name is recorded in metadata and may contain encoded/collision suffixes, so consumers should use generated output or metadata rather than guessing it.

| Generated member | Purpose |
| --- | --- |
| `$lyra$create()` | Create an instance with default runtime options on the calling owner thread |
| `$lyra$create(RuntimeOptions)` | Create with explicit immutable options |
| `$lyra$metadata()` | Return artifact metadata |
| `name(args...)` | Invoke a public function, unless the name is reserved/colliding |
| `invoke$name(args...)` | Invocation spelling for reserved/colliding names such as `close` |
| `get$name()` | Read a public value |
| `value$name()` | Read a public function value |
| `set$name(value)` | Replace a public `@mut` export |
| `close()` | Close the module instance |

Facade methods use exact Java types. There are no public representation fields or Java overload resolution. Java values supplied for `Fn` parameters/setters must be authenticated Lyra closures from the same open loaded artifact; arbitrary Java SAM implementations fail with `LYR-LINK`.

## Loading, instances, and lifecycle

`LyraRuntime.load(artifact, options)` or `load(path, options)` returns one verified loading context. Metadata is preflighted before generated classes are defined. A `LoadedArtifact` may instantiate module handles. Each root instance owns exactly one instance of every reachable dependency.

A module is confined to its creating thread. Facade calls, export handles, closures, and close enforce this with `LYR-THREAD`. Lifecycle is `INITIALIZING -> OPEN -> CLOSED`, with terminal `FAILED` if construction fails. Close is owner-thread-only and idempotent. Post-close access fails with `LYR-CLOSED`.

Close every module before its `LoadedArtifact`. Closing a context with open instances fails with `LYR-LIFECYCLE` and does not partially close it. Context close invalidates handles, releases caches, and closes its child loader; JVM class unloading is not guaranteed. Reload means compile/load a new instance. Existing values are not retargeted and state is not migrated.

`ExportHandle` validates export name plus canonical Lyra signature once and exposes an already bound exact `MethodHandle` and `MethodType`. Repeated invocation performs no name lookup, overload search, or `Object...` conversion.

This is a trusted Java boundary. It does not sandbox source, defend against malicious bytecode, impose quotas, or isolate the host process.
